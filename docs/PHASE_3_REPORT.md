## 2. 数值来源与缺失项

主方案17节提供四普通敌人的生命与单次伤害；18／18.1节提供精英420/18、约25%甲减伤和60%新增砸地；20.1节提供Boss1100、22/28/24及55%阈值。实际由resources/enemies六份Resource读取。

主方案未完整定义移动速度、感知／脱战范围、逐招前摇／生效／收招／额外冷却、射程、连击段间隔、弹速／寿命、身体尺寸、抗打断／阶段演出、护甲总量／削甲值和冲击波独立伤害。它们均作为阶段3测试参数公开记录于ENEMY_BALANCE.md和Resource，不能称正式已定值。例如速度依次165/65/225/100/85/95；Boss地波暂借28测试，精英冲撞／砸地暂用基础18。主角原有生命100、剑14/18/24、闪避规则均未覆盖。

缺失的灵气／灵石数量、装备与材料概率权重、正式奖励表和剧情道具ID没有伪造。死亡一次发出reward_requested事件，含source_id、enemy_id、drop_rates_defined=false、amounts_defined=false；Boss额外含确定材料名“筑基灵髓”。精英不会发筑基灵髓。路线已消费事件做去重和显示，但**没有奖励库存到账、随机抽装、成长、剧情或永久存档**；这是实际事件接口验收，不是完整掉落系统完成。

精英护甲可由receive_hit的armor_damage参数真实削减并破甲硬直，但玩家重击尚未实现，因此不宣称完整破甲教学通过。入场／转阶段暂不受伤、Boss及有甲精英预警／攻击抗打断，是开发方测试取舍，后续需手感评审。

## 6. 审查与修复

独立只读审查提出三项P2，全部修复并以先失败再通过验证：

1. 灵弩过近后撤速度被后续射程分支清零。改为后撤／射击互斥，新增近距实际位移断言。
2. Boss跳砸被平台提前截断，实际落点与地面预警不符；落地后还滑动。改按实际物理步长与环境射线预测首个落点、匹配预警高度，落地同帧伤害并停止横移。
3. 额外冷却被收招递减耗尽。改为收招结束才启动冷却，新增剩余冷却与期间不再射击断言。

进一步回归发现Boss落上平台后不能追踪下方玩家，已先失败再修复当前单向平台下降／碰撞恢复和预测排除。旧失败证据review-regressions-red.log、platform-follow-red.log保留为历史，不能与最终通过日志混淆。

独立审查未重复整套测试；最终完整回归由主代理实际执行。审查列出的正式动画／平衡、奖励到账／成长存档、Windows发布及外部文件变动均按本轮明确边界保留，不擅自补做或报通过；没有遗留本轮已知阻断缺陷。

## 8. 遗留项与阶段结论

本轮功能与可执行验收范围通过：六敌具实际差异、可攻击受伤死亡，Boss可入战、发动五类攻击、受伤、转阶段及一次死亡结算，六房固定路线清场切换与回祭坛可运行。

需要后续确定的主要输入：六敌测试速度和招式时间的试玩反馈、护甲／削甲量、冲击波独立伤害、奖励数量和概率、正式透明动作资产。它们不冒充本轮已冻结规则。当前停止，等待阶段4指令。
