# 《烬山问道》美术规范与角色动作流程

版本：0.1。日期：2026-10-22。状态：阶段 0 规范，尚未生产新素材。

基准：[完整方案](../GAME_DEVELOPMENT_PLAN.md)。现有素材：[主角三视图](../主角形象/主角.png)。用户负责提供三视图；动作制作方法由开发方解释并在阶段 1 验证，不要求用户先掌握建模。

## 1. 视觉基准

沿用墨黑、暗青蓝、月白、雾气、局部灵光与手绘东方奇幻。主背景 #07141B，暗青蓝 #153642，灵气高光 #83DCE8，月白 #D7E2E2，朱红 #9E302A，暗金 #B89A60。

现有三视图青白衣饰华丽，原方案偏旧衣、暗红腰带、风化旧剑。最终服饰方向需在阶段 1 制作前由用户确认；不能擅自重画或覆盖原图。复杂衣饰应先缩到实际尺寸检查，不把大图细节全部转换成动画要求。

启动检查时第一地图目录为空。交付复查发现该目录新增 9 张外部提供的怪物与 NPC 图片，保留原位，尚未做画面及动画可用性评审，不纳入本次文档提交。仍未发现剑冢环境参考图，不能声称已有场景资产。

新增文件包括阿蘅、顾长庚、沈砚舟、断刃游魂、腐甲尸兵、裂甲山魈、灵弩傀儡、山魑幼体、镇山妖将。精英和 Boss 图当前位于“小怪形象”目录；“山魑幼体”与方案“山魈幼体”有命名差异。阶段 1 统一核对，本次不移动或重命名。

## 2. 是否需要三维建模

首选路线：二维侧视角色，常态动作可用二维分层骨骼，攻击与闪避使用关键姿势或逐帧补绘。与主方案关键动作优先逐帧的要求一致。

三视图用于统一头身比、服装、背面和武器细节，不会自动变成模型或动画。二维骨骼所谓“建模”主要是拆层、补全遮挡部分、设置关节和绑定；不是必须制作三维网格。

| 路线 | 需要准备 | 适用与成本 |
|---|---|---|
| 手绘逐帧 | 每个动作的关键姿势和中间帧 | 攻击姿势自由、风格明确；绘制工作较多 |
| 二维分层骨骼 | 分层部件、遮挡补绘、关节位置 | 待机和移动便于复用；大幅转身和挥剑需补绘，不能靠旋转三视图解决 |
| 三维建模后渲染成二维 | 模型、贴图、绑定、动作、灯光及渲染 | 可统一多视角，但新增完整三维生产流程；本项目当前不采用 |

Godot 提供 AnimatedSprite2D、AnimationPlayer 及二维分层动画能力，不需要先购买第三方骨骼插件。Krita 支持手绘逐帧；这只是制作选项，不表示本机已安装或本次授权安装。

## 3. 三视图之后怎么做

1. 确认最终服饰方向和游戏侧视角。横版实战以侧面或轻微侧转视角为主，正背面主要作为设计依据。
2. 阶段 1 将角色置于目标画面比例下做静态尺寸评审，确认身高、武器长度与敌人可读性；不在阶段 0 凭空指定像素高度。
3. 根据选定路线制作透明侧视角色：逐帧路线先画关键姿势；分层路线拆头、躯干、骨盆、上下臂、手、大小腿、脚、头发、衣摆和武器。
4. 被袖子或躯干挡住的部位要补画；远近肢体分层，关节有重叠，避免动作时露洞。武器独立，握持点固定。
5. 先验证待机、奔跑、普通攻击第一段。攻击包含预备、有效挥击和收招；用实际尺寸观看是否滑步、穿帮或武器失去力度。
6. 三个动作通过后再扩展跳跃、落地、闪避、受击、死亡、重击、三连段、技能、交互及突破。长枪必须有不同握姿和攻击动作，不能只替换剑图。
7. 阶段 2 建工程，阶段 3 在引擎里绑定动作时间和命中窗口；正式资产可在阶段 11 替换，不把静态概念图冒充完整动画。

阶段 1 的验证可用静态样张或少量动作预览，不必为预览提前搭建游戏工程。正式战斗程序在后续阶段制作。

## 4. 动画交付规范

- 原始三视图完整保留，工作副本进入 assets/ 时另存；有分层源文件则保留，扁平 PNG 仍需补拆层工作。
- 动画导出透明 PNG 序列或图集，不能用带灰背景的三视图直接充当精灵。
- 同一动画集固定画布、角色比例和脚底基准，不逐帧裁切造成跳动。
- 记录脚底枢轴、握持点、帧顺序、逐帧时长，以及前摇／命中／收招窗口。
- 动画时长与帧数经手感验证确定，不提前统一为同一帧数。
- 文件名示例：`shen_jin_sword_attack_01_0001.png`；动作标识用英文，制作说明与 UI 用中文。
- 翻转后检查武器、衣摆与不对称装饰；不能默认水平镜像永远正确。

程序可以负责播放、状态切换、时间窗口、碰撞和预览；高质量姿势、遮挡补绘及稳定笔触需要美术制作与逐帧校正。不能承诺仅凭三视图自动得到正式可用的全套动作。

## 5. 环境与 UI

场景按远景、中景、近景、Gameplay、前景、Atmosphere、Lighting、Interactive 分层。碰撞体不跟随装饰轮廓随意改变，前景雾气不能遮挡攻击预警。

gl_compatibility 下先验证雾层、光束贴图和局部二维光效，不以未经实测的实时体积光作为前置条件。首版只验证一个剑冢画面及 HUD，不批量生成其他区域。

中文字体用 SystemFont，优先 Microsoft YaHei UI，不复制系统字体。音频与外部资产记录来源和授权；尚无素材时不编造授权结论。

## 6. 阶段 1 验收

方向经用户确认；角色实际尺寸下剪影清晰；待机／移动／攻击路线可行；武器与握点稳定；背景不掩盖角色、平台和敌人；动画交付规范足以指导后续制作。
